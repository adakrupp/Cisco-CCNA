### Ethernet LAN Switching
- Involves Layer 1 and Layer 2 of the OSI model
	- Physical and LAN/Data Link
- A LAN is a network contained within a small area
- Switches do not separate LANs, but can expand LANs
- This will focus on how switches receive and forward Ethernet frames

### Ethernet header and trailer

Below is an Ethernet frame:

![](Screenshots/Pasted%20image%2020260228175052.png)

In the header, there are the following fields:
**Preamble**
- 7 bytes long (or 56 bits)
- Alternating 1's and 0's
- 10101010 * 7
- Allows devices to synchronize their receiver clocks

**SFD(Start Frame Delimiter)**
- 1 byte long (8 bits)
- 10101011
- Marks the end of the preamble and the rest of the frame

**Destination and Source**
- 6 byte (48 bit) address of the physical device
- Indicates the devices sending and receiving the frame
- Consists of the destination and source 'MAC address'
- MAC=Media Access Control

**Type or Length**
- 2 bytes (16 bits)
- Can represent the type or length of the encapsulated packet
- If the value is 1500 or less, it indicates the LENGTH of the encapsulated packet
- If it is greater than 1536, it indicates  the TYPE of encapsulated packet (usually IPv4 or IPv6) and length is determined by other methods
- IPv4 = 0x0800 or 2048 in hexadecimal
- IPv6 = 0x86DD or 34525 in hexadecimal

In the trailer, there is only one field:
**FCS (Frame Check Sequence)**
- 4 bytes (32 bits) long
- Detects corrupted data by running a CRC algorithm over the received data
- CRC = 'Cyclic Redundancy Check'

7 + 1 + 6 + 2 + 4 = 26 bytes for the header and the trailer.

### MAC Address
- 6-byte (48-bit) physical address assigned to the device when it is made
- AKA Burned-In-Address
- Globally unique
	- No two devices should have the same MAC address
- The first 3 bytes are the OUI (Organizationally Unique Identifier) which is assigned to the company making the device
- The last 3 bytes are unique to the device itself
- Written as 12 Hexadecimal characters

### Hexadecimal system
**Decimal system**
- In the decimal system, Numbers 1-9 are used
- For example, the number 7 is 7 values of 1
- When we reach the number 10, it is 1 value of 10, and 0 values of 9
- When we have a number after that, like 29, it is 2 values of 10 and 9 values of 1
- When we reach 100, it is 1 value of 100, 0 values of 10, 0 values of 1
- And so on...
**Hexadecimal system**
- In the Hexadecimal system, there are 16 possible digits
- 0-9 and A-F
- A-F represent numbers
10=0A
11=0B
12=0C
13=0D
14=0E
15=0F
Then it starts over with numbers.
16=10
17=11
And so on. Once we reach 26, it would start over at 1A. Below is a full chart up to 255 or FF.

If a MAC address were like this:
AA.AA.AA.00.01

It would mean:
202.202.202.00.01
The first 3 sets of A's would be the OUI.

Let's say we're sending a single frame from one target to anther. This would be called a Unicast frame.

First, the frame would be sent to the switch. The switch would them add the device's MAC address to its MAC interface table and associate it with an interface, such as F0/1. This is called a Dynamically learned MAC Address or Dynamic MAC Address.

After that, since it wouldn't know where the other device is on this alone, it does something called 'Flooding' the frame. This is where it sends the frame to all of the other devices. It is also called an "Unknown Unicast Frame". Then, any device that the packet doesn't match simply drops the packet. 

Then, the device that receives the packet, and if there is no requirement for that device to send a message back, the interaction stops there. The switch never learns the MAC address on that info alone. 

If the second device then sends a message back, then the switch will add the MAC address to its MAC Address Table and sends the message back to the first one only. This is called a 'Known Unicast Frame' because the switch already knows the destination MAC address. Known Unicast Frames are simply forwarded. 

On Cisco switches, these addresses are removed from the MAC address table after 5 minutes of inactivity. 

**Unicast frame:** A frame destined for a single target

**Dynamically Learned MAC Address:** A MAC address learned when the device sends a frame to another device

**Unknown Unicast Frame:** A frame that is flooded, or sent to all devices on the network, because the destination MAC address is unknown or not on the MAC address table

**Known Unicast Frame**: A frame that is forwarded only to the device that is meant to be the recipient because the MAC address is on the switch's MAC Address table.
