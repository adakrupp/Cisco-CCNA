Physical difference between routers and switches:
- Routers will have less interfaces, especially UTP interfaces, but may have more Fiber Optic Interfaces
- Switches will have more UTP interfaces but may have less Fiber Optic interfaces
- This is because switches are used to connect end hosts to

In Cisco switches, when a cable is connected to an end host, the status will be up and the protocol will be up, even without configuration. This is because switches are administratively enabled, unlike routers. We call this 'up/up' See below.

![](/Screenshots/Pasted%20image%2020260304153057.png)

The interfaces that are down and down (down/down) are like this because they are not plugged into anything. This is different from 'administratively down'. To summarize

- Router interfaces have the shutdown command applied by default, so interfaces will be in the administratively down/down state by default
- Switch interfaces do NOT have the shutdown command applied by default, so they will be in the up/up state if connected or the down/down state if not connected by default. 

Let's look at the interface status for a switch.

`show interfaces status` - shows the interface status

- Port - Lists each interface
- Name - Description of the interface
- Status - Shows connected, notconnect, or other statuses
- Vlan - Shows vlan status. Default vlan is 1. 
- Duplex - Indicates whether the device is capable of sending and receiving at the same time. 
- Speed - Shows speed. 'a' means 'auto'
- Type - Shows the type of connection. 'a' means 'auto'

Let's say you have a Fast Ethernet connection, but want it to only go at regular Ethernet speeds. To manually configure an interface's speed, use these commands:

`conf t`

`int [interface]`

`speed [speed]`

For example:

`int f0/1`

`speed 100`

To configure duplex, use the following commands:

`duplex full` or `duplex half` or `duplex auto`

To set the name, you can use the `description` or `desc` command, like so:

`desc ## to R1 ##`

Next, if you are not using certain interfaces, that can be a security concern. For example, someone could plug a rogue access point into one of those switches. You can use the `shutdown` command as before to do that. However, if you have a range of interfaces, you can use the `interface range` command, as below:

`interface range [first interface] [last interface]`

For example:

`interface range f0/5 - 12`

Then, you'd just use the `shutdown` command for it to apply to all of them. 

The interfaces don't need to be consecutive, though. For example, you could use the command like this:

`int range f0/5 - 6, f0/9-12`

And then apply your command, such as `no shut`

Remember to save your configurations to the startup config with `wr` when you are done!

### Full/Half Duplex
- **Half duplex** - The device cannot send and receive data at the same time. If it is receiving a frame, it must wait before it can send one. Devices attached to a hub must use half duplex
- **Full duplex** - the device can send and receive data at the same time without waiting. Devices attached to a switch can use full duplex.

**Where is half duplex used?**
In modern devices, nowhere. It used to be used with hubs back when they were used regularly. Unfortunately, when two devices sent something to another device at the same time, it would result in a **collision**, and neither frame would be sent to that device.

#### CSMA/CD
- Carrier Sense Multiple Access with Collision Detection
- Before sending frames, devices 'listen' to the collision domain until they detect that other devices are not sending
- If a collision occurs, the device sends a jamming signal to inform the other devices that a collision happened
- Each device will wait a random period of time before sending frames again
- The process repeats
- This is how networks worked for a long time
- Hubs work on Layer 1, simply passing messages along. Switches operate at Layer 2.

### Autonegotiation
- Interfaces that can run at different speeds (10/100 or 10/100/1000) have default settings of speed auto and duplex auto
- Interfaces advertise their capabilities to the neighboring device, and they negotiate the best speed and duplex settings they are both capable of.
- If autonegotiation is disabled:
	- Speed - the switch will try to sense the speed the other device is operating at. If it fails to sense the speed, it will use the slowest supported speed. If autonegotiation is off and there is a duplex mismatch, there will be collisions.
	- Duplex - If the speed is 10 or 100 Mbps, the switch will use half duplex. If the speed is 1000 Mbps or greater, the switch will use full duplex.

### Interface Errors
You can use the `show interfaces` command to also show errors. Here are the types of errors:

- Runts - Frames smaller than the minimum frame size (64 bytes)
- Giants - Frames larger than the maximum frame size (1518 bytes)
- CRC - Frames that failed the CRC in the Ethernet FCS trailer
- Frame - Frames that have an incorrect format due to an error
- Input errors - Total of various counters like the above four
- Output errors - Frames the switch tried to send but failed due to an error
