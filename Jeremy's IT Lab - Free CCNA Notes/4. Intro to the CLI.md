
### How to connect to a Cisco device via CLI
- Use the console port on the device
- RJ45 connector (rollover cable) 
- RJ-45 on one side, serial port on the other.

![](/Screenshots/Pasted%20image%2020260228142315.png)

- Most laptops don't have a serial port anymore, so you need an adapter.
- USB-Mini-B

### How to access the CLI
- Terminal or terminal emulator
	- PuTTY

![](/Screenshots/Pasted%20image%2020260228142414.png)

- Speed: 9600
- Data bits: 8
- Parity: None
- Flow control: None

When you connect to a Cisco router, the default name is 'Router'. You will land in User Exec Mode.

**User EXEC Mode**
- Very limited
- Can look at things but can't change anything
- Also called user mode
- Enter 'enable' command to be placed into Privileged EXEC mode

**Privileged EXEC Mode**
- Default name changes from 'Router>' to 'Router#'
- Provides complete access to view configuration, restart the device, etc
- Cannot change the configuration, but can change time on the device, save the configuration file, etc

![](/Screenshots/Pasted%20image%2020260228143045.png)

You can use a `?` to view the commands available. You can also use the tab key like in a normal terminal to complete commands.

You can also use a question mark after a letter in order to view all commands that start with that letter. So if you typed `r?`, it would show reload, resume, rmdir, etc. 

Once you're in Privileged EXEC mode, you can type in `configure terminal` to enter global configuration mode. 

**Global Configuration Mode**
- In Global Configuration Mode, the router name will have a (config) added after the name, like 'Router(config)#'
- You can type in `configure terminal` or just shorten it to `conf t` and get into this mode.
### Configuration files
**Running Config**
- Current, active configuration file on the device. If you enter commands in the CLI, you are editing the active configuration
- Use `show running-config` to view
- Use `write`, `write memory`  or `copy running-config startup-config` to save the running config file as the startup config file

**Startup Config**
- The configuration file that will be loaded upon restart
- Use `show startup-config` to show it
- This needs to be saved before it will show

**Passwords**
Below, there are several commands regarding a password.
1. To edit the password, you need to be in Global Configuration Mode.
2. The first command, with no space between 'password' and '?' shows the one option available, password
3. The next command, with a space between 'password' and '?' shows the allowed options. One of them is LINE, which shows a cleartext password is allowed to be entered after the word 'password' 
4. The third command, `enable password CCNA ?`, shows that there are no further options available. That is what the `<cr>` means.
5. The 4th line, `enable password CCNA`, sets the password to 'CCNA'

![](/Screenshots/Pasted%20image%2020260228143649.png)

- This is inherently not secure, so we can encrypt the password itself using the command `service password-encryption`.
- The '7' below indicates it is using Cisco's proprietary encryption. This is actually still pretty easy to crack. You could google 'Cisco password type 7 encryption cracker' and put in the '08026F6028' and easily crack the password.

![](/Screenshots/Pasted%20image%2020260228144745.png)

The more secure method is to enable the `enable secret` command. 
- First use `enable secret [password]` where you replace the password in brackets with the actual password you want to use.
- This enables MD5 encryption
- Then use the command `do sh run` to run the command and encrypt the password.

![](/Screenshots/Pasted%20image%2020260228145147.png)

So basically, do not use the `service password-encryption` command, and do use the `enable password` command because it is always going to use stronger encryption.

### Cancelling commands
- Type a 'no' before the command
- For example `no service password-encrpytion` would make it so that future passwords are not encrypted.
- This would not have any effect on the current password regardless of if it's encrypted or not, so if you type in the password after trying to enter global configuration mode, it would still allow you onto the device
