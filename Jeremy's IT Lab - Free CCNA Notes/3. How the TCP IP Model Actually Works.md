
Protocol - A set of rules defining how data should be communicated between devices over a network.
- Often developed by a specific vendor
- This created a proprietary approach which was difficult to manage

Standard - An agreed upon specification that describes how a protocol or technology should work.
- Vendor-neutral standards make it possible for all types of devices to communicate

### History
- Internet began in the 1960's as ARPANET from the Dept of Defense's ARPA
- Connected mainframes at universities and labs
- Used a protocol called NCP (Network Control Program)
- TCP began developing in 1974
	- Later divided into two protocols: TCP and IP
		- Transmission control protocol
		- Internet Protocol

### Who defines standard?
IEEE - Institute of Electrical and Electronics Engineers
- Develops many technologies on LANs
	- Ethernet (802.3)
	- Wi-Fi (802.11)
IETF - Internet Engineering Task Force
- Open community that defines protocols
	- TCP, IP, UDP, HTTP, DNS
- Publishes standards in documents called "RFCs" (requests for comments)


## Layered Models
A model lets us group related jobs into layers
- Each layer has a specific role
- Each layer uses the services below and provides services to the layer above
 
Protocols live mostly at one layer
- Ex IP, TCP, HTTP
- Together they form a stack of protocols that work as a team (the network stack)
### The TCP IP Model
1. Physical layer - Physical devices
2. Local Network layer - Ethernet, Wifi
3. Internet layer - IPV4, IPV6, ICMP
4. Transport layer - TCP, UDP
5. Application layer - Telnet, FTP, TFTP, etc

**Layer 1 - Physical**
- Sends bits as electrical, optical, or radio signals over the physical medium
- Defines things like cables, connectors, signal levels, and link speeds
- Examples are copper UTP cables, fiber-optic cables, Wi-Fi radios and antennas, network interface cards(NICs)
- Physical aspects of transmitting data are very complex, but luckily, network engineers don't have to know low-level details. 

**Layer 2 - Local Network**
- Provides hop-to-hop delivery within a local network using MAC addresses and switches
- A hop is one step on the path between two devices
- Switches don't count as hops; they just extend the network
- Uses MAC (Media Access Control) addresses to identify interfaces.
- Key protocols for this layer are Ethernet (802.3) and Wi-Fi (802.11)

**Layer 3 - Internet**
- Provides end-to-end communication between hosts across networks using IP addresses and routers
- Internet = internetwork (between networks)
- IP addresses identify hosts within the network
- Routers operate mainly at this layer, using the destination IP address to forward to the final destination
- Protocols include:
	- IP (IPv4, IPv6)
	- ICMP (Internet Message Protocol)


**Layer 4 - Transport**
- Provides end-to-end communication between application processes using port numbers
	- Process-to-process or service-to-service
- Uses port numbers to identify the processes on each host
- Runs mainly on the communicating hosts; routers run on IP (layer 3), not Transport-layer
- Protocols include: UDP (User Datagram Protocol) and TCP (Transmission Control Protocol)

**Layer 5 - Application**
- Protocols for communication between application processes; create and interpret data
- Where network communications meet applications
	- Usually called Layer 7
- Define message formats and rules for specific tasks
	- HTTP for browsing web pages
	- FTP/TFTP for transferring files
	- POP3 and SMTP for emails
- Network infrastructure devices don't care about Application-layer details
	- They just move messages across the network
	- Only the communicating hosts interpret data

### Encapsulation and decapsulation

Each device has its own network stack. When information is sent, it goes down one stack, crosses the wire to the other network, then goes up the other stack. These are the processes that occur when that happens.
#### Encapsulation
![](/Screenshots/Pasted%20image%2020260227183652.png)

1) Application layer prepares the data to be sent over the network
2) As the message moves down the stack, each layer encapsulates the data with a header including information needed for that layer
	- Source and destination addresses (Port numbers, IP addresses, MAC addresses)
	- Layer 2 also adds a trailer that the receiving device uses to check for transmission errors
- The Physical layer transmits the bits as signals over the physical medium
	- The L2 header is transmitted first, and the L2 trailer is transmitted last.
#### Decapsulation
![](/Screenshots/Pasted%20image%2020260227184234.png)

1) The receiving device receives the message at layer 1 as a stream of bits
2) The device examines the info in the Layer 2 header and trailer, then removes them
3) This continues up the stack; Layer 3 removes the L3 header, Layer 4 removes the L4 header, and then the data is delivered to the application layer
4) Application processes the data and if needed, generates a response that goes back down the stack

### Protocol Data Units
At each stage in the encapsulation/decapsulation process, there is a name given to the message.
- The combination of data and L4 header is called a segment (TCP) or datagram (UDP)
	- TCP creates segments, UDP creates datagrams
- The combination of a segment or datagram and the L3 header is called a packet
- The combination of a packet and an L2 header/trailer is called a frame
	- Frames are what are sent over the wire

We can use alternative names to describe the message at each stage: Protocol Data Unit (PDU)
- A segment or datagram is a Layer 4 PDU
- A packet is a Layer 3 PDU
- A frame is a Layer 2 PDU

The contents of each PDU is called the payload. The payload is what's *inside* the PDU, not including that layer's header or trailer.
- A segment or datagram's payload is the application data
- A packet's payload is the segment or datagram
- A frame's payload is a packet

### Adjacent-Layer interaction
![](/Screenshots/Pasted%20image%2020260227185138.png)

Each layer provides a service to the layer above it, and is services by the layer below it (called adjacent-layer interaction)
- Layer 4 provides Layer 5 with the service of delivering data to the correct application using port numbers
- Layer 3 provides a service to Layer 4 by delivering segments/datagrams to the correct destination host using IP addresses
- Layer 2 provides a service to Layer 3 by delivering packets to the next hop using MAC addresses
- Layer 1 provides a service to Layer 2 by sending and receiving frames like electrical, optical, or radio signals


### Same-layer interaction
![](/Screenshots/Pasted%20image%2020260227185441.png)

Each layer communicates with the same layer on other devices (called same-layer interaction)
- Application layer on one host sends data to the Application layer on another host
- A segment/datagram is addressed to the Layer 4 port number of the correct application on the destination host
- A packet is addressed to the Layer 3 IP address of the destination host
- A frame is addressed to the Layer 2 MAC address of the next hop
- Signals sent out of a physical port are received by a physical port on the connected device

### Separation of layers
- Each layer has its own job and provides a specific service to the layers above
	- The layers are modular
- As long as each layer keeps its "contract" with the other layers, we can improve or replace protocols at different layers without redesigning everything
- This flexibility is one of the main benefits of a layered model

### The OSI Model
![](/Screenshots/Pasted%20image%2020260227190041.png)

- The ISO (International Organization for Standardization) designed the 7-layer OSI (Open Systems Interconnection) model and a matching protocol suite in the 1970's and 1980's
- The goal was to create international, vendor-neutral networking standards that could unify existing proprietary stacks and potentially replace TCP/IP
- Great acronym: Please Do Not Throw Sausage Pizza Away
- Governments promoted OSI as preferred/recommended stack for new deployments
- OSI was late and complex, and never gained the same deployment as TCP/IP
	- Some OSI technologies are still used
- Most real networks use TCP/IP but the 7-layer OSI model survives as a reference and common way to talk about 'layers'
- Most networking resources use a 5-layer model 
	- This is why the Application layer is often called "Layer 7"
